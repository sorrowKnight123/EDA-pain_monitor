### 7.68 串口IAP在线升级实验（p.786-798）

| 字段 | 内容 |
|------|------|
| 外设/模块 | USART1（串口1，与处理器相连 PA9、PA10）、STM32 内部 Flash（512K，STM32F103ZET6）、按键（原文 WAMPER/TAMPER/USER2，对应代码中 KEY_UP/KEY_DOWN/KEY_LEFT） |
| 接口/总线 | 串口（RS232/USART），无校验、一次性接收 APP 程序 |
| 关键引脚 | PA9、PA10（串口1 与处理器相连的两个管脚） |
| 时钟使能 | 手册未明确（仅提到系统启动文件调用 SystemInit() 初始化 72MHz 时钟） |
| 关键 API / 寄存器 | SZ_STM32_COMInit()（串口初始化）、SZ_STM32_KEYScan()（按键扫描，返回按下键值）、iap_write_appbin()、iap_load_app()（参数 appxaddr 为 APP 程序起始地址）、串口中断函数；MDK 工具 fromelf.exe（--bin -o 生成 .bin）；中断向量表偏移量设置 |
| 初始化步骤 | 1）定义按键，为判断按键值做准备；2）定义 APP 代码长度标识符；3）串口与按键初始化，串口初始化完后打印 "Bootlader!"；4）进入死循环等待串口中断接收数据，接收完打印提示符与代码大小；5）按 KEY_UP 时判断地址是否正确并更新 Flash 固件（地址错误则打印错误提示）；按 KEY_DOWN 清除 Flash 已有固件（没有则提示"没有可清除的固件"）；按 KEY_LEFT 运行 Flash 里的 APP 程序（无程序或非 Flash 程序则打印"非FLASH 应用程序,无法执行"） |
| 常见坑 / 注意 | 串口接收 APP 程序无校验、一次性接收；Bootloader 程序越小越好，不能大于 0x10000（本例编译约 6K）；APP 起始地址须在 Bootloader 之后且偏移量为 0x200 的倍数（本例选 0x08010000，偏移 0x10000=64K，APP 空间剩 448K）；必须同时设置 APP 程序起始地址与中断向量表偏移量；MDK 默认生成 .hex 不便 IAP 更新，需用 fromelf.exe 转 .bin；STM32 在对 Flash 实行读保护时会自动把用户 Flash 区开始 4 页设为写保护，防止 IAP 程序被意外破坏；第一部分（Bootloader）必须通过 JTAG 或 ISP 烧入 |
| 依赖前置 | 需了解 STM32 正常程序运行流程与中断向量表；第一部分代码须先用 JTAG/ISP 烧入；第二部分（APP）由第一部分 IAP 功能烧入 |

**一句话作用**：通过串口1 接收上位机下发的 APP 程序（.bin）写入 STM32 内部 Flash，实现产品发布后免拆机的固件在线升级（IAP），并用按键控制更新/清除/运行 Flash 中的 APP。

### 7.69 MP3(VS1003)音频模块实验（p.799-812）

| 字段 | 内容 |
|------|------|
| 外设/模块 | VS1003 音频解码芯片（LQFP-48/BGA 封装，含 VS_DSP4 核、5KB 指令 RAM、0.5KB 数据 RAM）、STM32 SPI1、系统定时器 SysTick |
| 接口/总线 | SPI（SPI1），VS1003 作为从机；VS1003 的串行数据接口 SDI 与串行控制接口 SCI |
| 关键引脚 | 模块 9 脚与开发板 I/O：XDCS=PE8（数据片选）、XCS=PE7（片选输入）、DREQ=PC13（数据请求）、SCLK=PA5（串行时钟）、MOSI=PA7（数据输入）、MISO=PA6（数据输出）、XRESET=PE6（复位）、GND、5V（VCC，可接开发板 3.3V） |
| 时钟使能 | 手册未明确（提到 SystemInit() 初始化 72MHz 时钟、SZ_STM32_SysTickInit(1000000) 初始化 SysTick） |
| 关键 API / 寄存器 | InitPortVS1003()（初始化 MP3 模块引脚）、SPI1_Init()（初始化 SPI）、VS_HD_Reset()（硬件复位，成功返回 0）、VS_Soft_Reset()（软件复位并设置时钟）、VS_WR_Data()、VS_SPI_ReadWriteByte()；VS1003 寄存器 SCI_MODE、SCI_BASS、SCI_CLOCKF、SCI_VOL、SCI_HDAT0/SCI_HDAT1；SCI 指令：读 0x03、写 0x02 |
| 初始化步骤 | 1）时钟选择：VS1003 工作于单时钟，12.288MHz 作为主时钟（外部电路接 XTALI，或内部晶振 XTALI/XTALO）；2）复位 VS1003：含硬复位（XRESET 拉低）和软复位（SCI_MODE 的 bit2，之后等待至少 2us），建议每首歌播放前都执行一次硬复位和软复位；3）配置寄存器：模式寄存器 MODE、时钟寄存器 CLOCKF、音调寄存器 BASS、音量寄存器 VOL 等；4）发送音频数据：只要 DREQ 变高就向 VS1003 发送 32 个字节，继续等待 DREQ 变高直到音频数据发完；5）播放/解码（SDI 数据被解码，采样率变换到内部模拟 DAC 允许的范围） |
| 常见坑 / 注意 | 每次 SCI 操作后 DREQ 线被置 0，不允许在 DREQ 变为 1 之前开始新的 SCI/SDI 操作，SCI 操作前最好判断 DREQ 是否为高、不是则等待；数据必须在 DREQ 信号控制下有序发送，不能乱发（DREQ 变高时发送 32 字节，DREQ 变低时必须停止）；DREQ 有 32Byte 保险区域（数据缓冲区），VS1003 直到 VS1002 DREQ 仅用于 SDI 传送，VS1003 中 DREQ 也用于告知 SCI 状态；复位函数用 `while(VS_HD_Reset())` 判断，成功返回 0 才跳出循环 |
| 依赖前置 | 需按模块引脚表用杜邦线一一对应连接模块与开发板；音频数据存放在 MP3Sample.h 文件的 music 数组中；需了解 SPI 相关内容（ST 官方库函数） |

**一句话作用**：通过 STM32 的 SPI1 向 VS1003 音频解码芯片发送 MP3 数据流（DREQ 高电平时每次发送 32 字节），实现 MP3 音乐播放，接耳机即可听到音乐。

| 接口/总线 | 单总线（红外接收头 DATA/OUT 接单片机外部中断，结合定时器判断间隔时间）；TIM4_CH4 输入捕获 |
| 关键引脚 | 红外接收头与神州3 号开发板连接：3.3V→VDD（杜邦线绿色）、PB9→DATA/OUT（杜邦线白色）、GND→GND（杜邦线红色） |

| 初始化步骤 | 1）STM32_Shenzhou_COMInit() 初始化串口；2）Remote_Init() 初始化红外遥控：初始化 IO 口并配置 TIM4_CH4 为输入捕获；3）TIM4_IRQHandler() 中捕获红外信号的高电平脉冲并按协议解码（识别数据"1"/"0"），用全局变量存储解码结果；4）Remote_Scan() 扫描解码结果，判断地址码与地址反码是否一致、键值是否一致，取出键值作为返回值；5）通过返回键值判断按下的按键并经串口输出 |
| 常见坑 / 注意 | 红外接收头与发射端电平互反（发射端高电平则接收头输出低电平），为保证解码方便编码时应直接换算成其反码；红外接收头有 VCC/GND/OUT 三脚，需焊接将开发板对应引脚引出；编码与解码是一对逆过程；数据"0"以脉宽 0.56ms 的电平开始、周期 1.12ms 的组合表示，"1"以脉宽 1.68ms、周期 2.24ms 的组合表示 |
| 依赖前置 | 需参考输入捕获实验（TIM4 配置与输入捕获实验基本接近）；用串口连接电脑、超级终端观察现象 |

**一句话作用**：用 TIM4_CH4 输入捕获检测红外接收头输出的脉宽（0.56ms/1.12ms 表示 0、1.68ms/2.24ms 表示 1），解码红外遥控器按键并经串口打印对应键值。

### 7.72 UCOSII操作系统之单任务运行（p.832-836）

| 字段 | 内容 |
|------|------|
| 外设/模块 | uCOS-II 实时操作系统（V2.91 版本）、LED 灯 |
| 接口/总线 | 无（操作系统内核，LED 原理图同 LED 流水灯） |
| 关键引脚 | 手册未明确（LED 管脚同 LED 流水灯） |
| 时钟使能 | 手册未明确 |
| 关键 API / 寄存器 | OSInit()（初始化 uCOSII 所有变量和数据结构）、OSTaskCreate()（创建任务，原型 `OSTaskCreate(void(*task)(void*pd), void*pdata, OS_STK*ptos, INTU prio)`）、OSStart()（启动多任务）；任务函数 Task_Shenzhou_LED()；类型 OS_STK（typedef unsigned int OS_STK，32 位） |
| 初始化步骤 | 1）初始化 LED 灯；2）调用 OSInit() 初始化操作系统所有变量和数据结构（必须在调用其他任何 ucos 函数之前调用）；3）用 OSTaskCreate() 创建任务：参数1 task 指向任务代码指针、参数2 pdata 传参指针（本例 `(void *)0` 表示无参数）、参数3 ptos 任务堆栈栈顶指针（本例分配 100 个 OS_STK 单元）、参数4 prio 任务优先级（本例设为 5）；4）Task_Shenzhou_LED() 内实现 LED 灯闪烁；5）调用 OSStart() 正式启动操作系统，任务才真正开始运行 |
| 常见坑 / 注意 | 任务是死循环函数，UCOSII 让多个任务并发工作（非同时工作，任何时候只有一个任务占用 CPU）；每个任务须有唯一优先级，UCOSII 不支持多个任务优先级相同；uCOS 一般默认占用最低 2 个优先级（空闲任务倒数第一、统计任务倒数第二），留给用户最多 253 个；早期版本只支持 64 个任务，V2.80 起支持 255 个；堆栈须声明为 OS_STK 类型、由连续内存组成，可静态或动态分配，本例栈顶地址为 &start_task_stk[START_TASK_STK_SIZE-1]；堆栈大小靠经验/检测确定，资源足够时可先设较大值再缩减 |
| 依赖前置 | 需先了解 LED 流水灯（LED 初始化）；建议先阅读任哲《嵌入式实时操作系统μC/OS-II原理及应用》等资料 |

**一句话作用**：在 uCOS-II 下用 OSInit() 初始化、OSTaskCreate() 创建 1 个优先级为 5 的任务、OSStart() 启动，任务函数 Task_Shenzhou_LED() 使 LED1 以固定频率闪烁。

### 7.73 UCOSII操作系统多任务运行（p.837-838）

| 字段 | 内容 |
|------|------|
| 外设/模块 | uCOS-II 实时操作系统、SysTick 系统定时器（与 UCOSII 共用）、LED 灯 |
| 接口/总线 | 无（操作系统内核，LED 原理图同 LED 流水灯） |
| 关键引脚 | 手册未明确（LED 管脚同 LED 流水灯） |
| 时钟使能 | 手册未明确（主函数首先配置系统时钟到 72M，并初始化使能 SysTick 定时器） |
| 关键 API / 寄存器 | OSInit()、OSTaskCreate()（本例 `OSTaskCreate(Task_Shenzhou,(void*)0,&start_task_stk[START_TASK_STK_SIZE-1],START_TASK_PRIO)`）、OSStart()；任务函数 Task_Shenzhou()、Task_1_Shenzhou()；宏 OS_TICKS_PER_SEC（设置 OS_TICKS_PER_SEC=100 即 10ms 节拍）；寄存器 RELOAD（SysTick 24 位倒计数定时器重装载） |
| 初始化步骤 | 1）配置系统时钟到 72M；2）初始化并使能 SysTick 定时器；3）配置神舟III 号 LED 灯使用的 GPIO 管脚模式；4）OSInit() 初始化 UCOSII；5）OSTaskCreate() 创建 1 个任务 Task_Shenzhou（栈 &start_task_stk[START_TASK_STK_SIZE-1]，优先级 START_TASK_PRIO）；6）OSStart() 启动 UCOSII 操作系统 |
| 常见坑 / 注意 | uCOS 运行需要固定系统时钟节拍（由 OS_TICKS_PER_SEC 设置，本例设为 100 即 10ms），STM32 下一般由 SysTick 提供、须设为 10ms 中断一次，且此节拍一般不能被打断否则不准；UCOSII 下 SysTick 一旦设定就不能随意更改，用其做 us/ms 延时时须整合计算（例：延时 100us 需等待 100/9 个 systick 计数，因每 systick 增加 1 相当于主频运行 8 次，8*(1/72MHz)=1/9us）；Task_Shenzhou() 中又创建了 1 个任务 Task_1_Shenzhou()；Task_Shenzhou() 在 while 死循环中执行 LED1 点灯闪烁，Task_1_Shenzhou() 在 while 死循环中执行 LED3 点灯闪烁 |
| 依赖前置 | 需先跑通 7.72 单任务例程；LED 流水灯实验（LED 管脚） |

**一句话作用**：在 uCOS-II 下创建 3 个任务，各任务分别控制不同的 LED（LED1、LED3）以不同频率闪烁，演示多任务并发运行，节拍由 SysTick（10ms）提供。

| 时钟使能 | 手册未明确 |
| 关键 API / 寄存器 | Init_LCD1602()（初始化 1602 屏）、write_com()（发送命令，rs=0 表示操作命令）、write_dat()（写数据）；内部寄存器：指令寄存器 IR、数据寄存器 DR、忙标识位 BF、地址计数器 AC、DDRAM、CGROM、CGRAM；关键指令：清屏 0x01（清 DDRAM 和 AC）、设置 DDRAM 地址（写地址时须 0x80+Address，如 0x80）、设置 CGRAM 地址（高 2 位固定 01，写入时先设 CGRAM 地址 0x40）；HD44780 共 11 条指令 |
| 初始化步骤 | 1）主函数初始化延时函数；2）Init_LCD1602() 初始化 1602 屏：用 PE0~PE7 作数据交流线，PC8/PC9/PC10 分别是 en/rw/rs，初始化后通过 write_com() 发送设置命令（如 0x01 清屏）；3）write_com() 发送命令（rs 为 0 表示操作命令），拉高拉低按读写时序图编写；4）while() 循环中先 write_com(0x80) 确定显示位置，再在 for 循环中通过 write_dat() 写入数据（数据定义在数组 table1[] 中）；5）显示字符 |
| 常见坑 / 注意 | 液晶是慢显示器件，执行每条指令前一定要确认忙标志 BF 为低电平（BF=0 不忙）否则指令失效；想在 DDRAM 的 00H 地址处显示数据必须将 00H 加 80H 即 80H（初学者易错点），第二行第一个字符地址 40H 也须加 80H；对比度端 V0 接正电源时对比度最弱、接地时最高，过高会产生"鬼影"（本例直接接地）；自定义字符先写入 CGRAM 再送 DDRAM 显示（CGRAM 字符码 0-2 位为地址、3 位无效、4-7 全为 0，实际 8 个可用） |
| 依赖前置 | 神舟III 开发板没有 1602 屏接口，需用杜邦线连接开发板与 1602 屏；下载固件后关闭电源再连线，连好后再上电 |

**一句话作用**：用 STM32 的 PE0~PE7（数据）与 PC8/PC9/PC10（en/rw/rs）并行驱动 1602 字符液晶屏，通过 write_com()/write_dat() 显示 "HELLO World" 字样。
